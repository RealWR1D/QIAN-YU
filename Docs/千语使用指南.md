# 千语使用指南

千语（QIAN YU）是一款支持 iPhone 和 Mac 的陪伴应用。你可以和陈千语聊天，整理课程表，接收课前与日常提醒，也可以用番茄钟安排一段专注时间。

这份指南按照 2026 年 10 月 4 日的项目源码编写。涵盖课程、提醒、聊天、备份和个人侧载安装的实际操作。较早的构建可能没有文中部分入口，请先核对安装版本。

项目源码：[RealWR1D / QIAN-YU](https://github.com/RealWR1D/QIAN-YU)。

## 1. 开始之前

### 系统要求

| 使用方式 | 要求 |
| --- | --- |
| iPhone | iOS 17 或更新版本 |
| Mac | macOS 14 或更新版本 |
| 从源码安装 | 一台 Mac，以及能编译项目的 Xcode |
| AI 聊天与 AI 每日问候 | 可用的 OpenAI 协议兼容接口、模型，以及服务商要求的 API Key |
| 天气问候 | 联网，并选择常用地点或获取一次当前位置 |
| 睡眠联动 | 在 iPhone 的快捷指令中配置自动化 |

没有 API Key 也可以使用课程表、提醒和番茄钟，聊天会使用内置语料，回复能力较有限。天气不需要你另外申请天气服务的 API Key。

灵动岛需要支持灵动岛的 iPhone。其他符合系统要求的 iPhone 可以使用课程表、普通通知和相应的锁屏实时活动。

下面的安装说明以从源码运行项目为例。若你已经安装了千语，可以直接从「第一次使用」开始。

## 2. 安装与启动

QIAN YU 提供 iPhone IPA 构建产物和项目源码。符合下列条件的用户可以使用自己的 Apple 账号重新签名安装；是否能够完成安装和续签，取决于设备、账号、网络及安装工具的支持情况。

安装包：[iPhone IPA 下载页](https://github.com/RealWR1D/QIAN-YU/releases/tag/ios-sideload)。本频道不是 TestFlight 或 App Store 分发，IPA 不能在「文件」应用中直接点击安装。应用不要求安装者购买开发者会员；使用免费账号签名时仍受 Apple 的有效期、能力及配额限制。

### 选择安装方式

| 方式 | 前置条件 | 更新与续签 |
| --- | --- | --- |
| Xcode 源码安装 | Mac、兼容的 Xcode、Apple 账号和 iPhone | 通过 Xcode 重新编译安装 |
| SideStore 安装 IPA | 首次设置需要兼容电脑；iPhone 上需完成 LocalDevVPN、设备配对及账号配置 | 完成设置后，可在满足网络条件时通过 SideStore 更新与续签 |
| AltStore Classic 安装 IPA | Windows 或 Mac 上运行 AltServer，完成设备和账号配置 | 通过 AltServer 配合 AltStore 更新与续签，仍需要电脑 |

免费签名一般有效 **7 天**，到期前需续签。SideStore 的手机续签能力不代表首次安装无需电脑，也不保证后台自动续签一定执行。具体兼容系统、工具安装及账号条件以各工具官方文档为准。

Xcode 源码安装步骤见本章下方。AltStore Classic 用户参阅 [Windows 安装](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows)及[官方说明](https://faq.altstore.io/altstore-classic/your-altstore)。以下介绍 SideStore 路线。

### SideStore 前置要求

- iPhone 运行 iOS 17 或更新版本，且满足所安装 SideStore 版本的要求。
- 准备一台兼容的 Windows、Mac 或 Linux 电脑、数据线和自己的 Apple 账号。
- 确认 App Store 所在地区可以下载 **LocalDevVPN**。若商店地区不提供该应用，此路线的前置条件尚未满足，应选择其他支持的安装方式。
- 按官方说明准备 iloader、设备配对及所需网络环境。

LocalDevVPN 使用的 Network Extensions 能力不向免费 Personal Team 开放，因此不能假定下载它的普通 IPA 再免费重签就能替代 App Store 安装。参见 [Apple 能力表](https://developer.apple.com/help/account/reference/supported-capabilities-ios)和 [SideStore 前置要求](https://docs.sidestore.io/docs/installation/prerequisites)。

### 首次安装 SideStore

1. 按 [官方准备指南](https://docs.sidestore.io/docs/installation/prerequisites)，在电脑安装 iloader，在 iPhone 安装 LocalDevVPN。
2. 用数据线连接 iPhone，解锁并确认「信任此电脑」。
3. 按 [官方安装指南](https://docs.sidestore.io/docs/installation/install)，使用 iloader 安装独立的 SideStore 并完成设备配对。
4. 根据系统提示开启开发者模式、信任对应开发者。使用自己的 Apple 账号登录 SideStore，完成首次刷新。

本项目使用独立安装方式，保留 QianYuWidgets 扩展。账号密码、验证码、设备配对文件和签名凭据应仅用于安装者自己的设备，不需要提交给项目维护者。

### 安装 QIAN YU

1. 在 SideStore 的 **Sources** 页面添加以下源：

```text
https://github.com/RealWR1D/QIAN-YU/releases/download/ios-sideload/sidestore.json
```

2. 刷新源，找到 **QIAN YU** 并安装。
3. 如询问是否保留扩展，保留 **QianYuWidgets**；移除扩展将无法使用课程小组件、锁屏专注和灵动岛展示。
4. 安装完成后打开应用，按本文第 3 章开始配置学期、导入课表、设置提醒，并按需配置 AI。

也可从下载页获取 `QIAN-YU-iOS-SideStore.ipa`，通过 SideStore 的 **My Apps → +** 导入，或使用支持该包的其他安装工具。

更换安装方式或应用标识前，可在 **设置 → 关于应用 → 备份与恢复** 导出数据。不同安装标识可能形成独立的数据容器，原有 Xcode 安装版可能被替换或共存；新安装后需检查数据并重新配置 API。

### 日常更新与续签

- 免费账号用户应在到期前，在 SideStore 的 **My Apps** 中刷新 **SideStore 和 QIAN YU**，定期检查剩余有效期。
- 按当前 SideStore 流程，安装、更新和续签时需要 Wi-Fi 并开启 LocalDevVPN；完成后可断开该本地 VPN。
- 新版本通过相同源地址提供。安装前可查看发布页的源码提交、构建信息和校验文件。
- SideStore 本身到期无法启动时，可能需要电脑重新安装。不要把后台刷新视作持续可用的保证。
- 免费账号的侧载应用数量及 App ID 配额有限。SideStore 本身占用应用名额，QianYuWidgets 还需要相应 App ID；遇到配额错误时按安装工具的提示处理。

参考：[SideStore 常见问题](https://docs.sidestore.io/docs/faq)及[错误排查](https://docs.sidestore.io/docs/troubleshooting/error-codes)。

### 构建与验证范围

构建为设备 arm64 Release，包含主应用、QianYuWidgets、头像和应用图标。侧载版使用应用容器内的本地数据库，按安装后的 App Group 共享课程数据。

自动检查覆盖回归测试、设备 Release 编译、IPA 结构、版本一致性、可执行文件和本地签名完整性。它们不等于已在所有设备和安装工具上通过验收。首次安装后请检查启动、课表保存、通知、聊天、专注实时活动和小组件。


### 获取项目

打开 [GitHub 仓库](https://github.com/RealWR1D/QIAN-YU)，选择 **Code → Download ZIP**，解压到本地。也可以用终端下载：

```bash
git clone https://github.com/RealWR1D/QIAN-YU.git
cd QIAN-YU
open "QIAN YU.xcodeproj"
```

在 Xcode 中打开的是 `QIAN YU.xcodeproj`，运行方案选择 **QIAN YU**。

### 安装 Mac 下载包

下载包名称为 `QIAN-YU-macOS-universal-local.zip`，同时包含 Apple Silicon 与 Intel 架构。只有 Release 明确列出该资产时才代表已提供下载；源码压缩包不是应用。

1. 下载并解压，将 `QIAN YU.app` 拖入「应用程序」。
2. 第一次打开可能提示无法验证开发者。确认包来自本项目后，在「系统设置 → 隐私与安全性」中选择“仍要打开”，按系统要求再次确认。
3. 本地签名包使用 macOS 登录钥匙串保存 API Key，与 Xcode 版本的受保护钥匙串分开。首次使用需重新填写 API Key；不要将密钥发给维护者。
4. 系统可能请求钥匙串访问授权，尤其在更新本地签名包后。只对确认来自本项目的应用授权。拒绝时密钥可能无法读取或保存；不要通过关闭系统安全功能解决。

下载包将课表和聊天保存在 `~/Library/Application Support/QIAN YU/LocalDistribution/`，不依赖需要开发者团队身份的 App Group 数据库，也不启用 CloudKit。它不会自动读取 Xcode 签名版本的课表和聊天；原有数据保留在原位置，可以先在原版本导出备份，再在新版本恢复；课表也可通过原始 `.ics` 文件重新导入。

该包采用 ad hoc 本地签名，没有 Apple Developer ID 签名或公证。“仍要打开”是用户确认来源后的系统操作，不能证明软件安全。小组件共享数据、通知和日历权限需要在实际安装环境验收。若下载包无法正常使用，可回到源码方式，选择 My Mac，用自己的账号在 Xcode 运行。

参考：[Apple：安全打开 Mac 应用](https://support.apple.com/en-au/102445)。

### 在 Mac 上运行

1. 在 Xcode 顶部的运行设备中选择 **My Mac**。
2. 按 **Command + R** 编译并启动。
3. 首次打开后进入设置，按需配置通知和 AI。

以后可以直接打开已编译的 App。在 Xcode 左侧找到 **Products** 下的应用产物，右键选择 **Show in Finder**，然后在 Finder 中双击打开。项目源码有变化时，需要重新编译，变化才会进入 App。

### 在 iPhone 上运行

1. 在 Xcode 的账户设置中登录自己的 Apple 账户。
2. 用数据线连接 iPhone，解锁并按提示信任这台 Mac。
3. 在项目的 **Signing & Capabilities** 中，为主应用和小组件目标选择自己的签名团队。
4. 如果出现 Bundle Identifier 或 App Group 的签名错误，先检查错误提示。主应用与小组件的共享组必须一致。若更换 App Group，需要同步修改两份 entitlements 及 AppInstallationIdentity.swift 中的组标识；随意只改其中一个，会影响共享课程数据。
5. 在 Xcode 顶部选择这台 iPhone，按 **Command + R**。
6. 如果系统要求开发者模式，在 iPhone 的 **设置 → 隐私与安全性 → 开发者模式** 中开启，按提示重启并确认。Apple 提供了[开发者模式说明](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。
7. 如果安装后提示开发者尚未受信任，在 **设置 → 通用 → VPN 与设备管理** 中按系统提示信任对应的开发者，再打开千语。

安装完成后，日常使用直接点击手机上的千语图标即可。只有更新源码、重新安装或签名失效时，才需要再次通过 Xcode 运行。

免费账户的 Personal Team 可以用于个人设备测试，但签发的安装描述文件会在 7 天后到期，到期后需要重新编译安装。详见 [Apple 开发者账户说明](https://developer.apple.com/help/account/basics/about-your-developer-account/)。重新安装时尽量沿用原来的应用标识；不要为了续签先删除 App，以免丢失本地数据。

## 3. 第一次使用

建议按下面的顺序完成初始设置：

1. 进入 **设置**，填写希望千语使用的称呼。
2. 打开 **每日提醒与上课通知**，按需授予通知权限。
3. 设置 **开学第一周起始日期**，核对页面显示的当前教学周。
4. 在课程表中手动添加课程，或导入学校提供的 `.ics` 课表。
5. 点击 **发送测试通知**，等待约 3 秒，确认通知能够出现。
6. 需要 AI 时，再填写接口、模型和 API Key，点击 **测试当前配置**。
7. 需要天气问候时，选择自己的常用城市和区。
8. 需要睡眠联动时，完成两项快捷指令自动化，再打开应用内的对应开关。

主要页面包括陪伴、课程表、专注和设置。Mac 使用侧边栏切换，iPhone 使用底部标签切换。页面名称和位置可能随版本稍有变化。

### 完成设置后，试用一遍

1. 在课程表切到本周，核对今天的课程时间和教室。
2. 在陪伴页发送「这个学期都有什么课？」或「明天有什么课？」，对照课表检查回复。
3. 开始一轮专注，切到课程表再返回，确认计时继续；不需要这一轮时点击重置。
4. 到 **设置 → 关于应用 → 备份与恢复** 导出一次备份，选择「文件」或自己信任的位置保存。

## 4. 设置学期与管理课程

### 先设置教学周

进入 **设置 → 每日提醒与上课通知 → 开学第一周起始日期**，填写学校实际的第一教学周起始日期。通常应使用学校规定的第一周周一，不能只凭报到日期推算。

教学周用于判断单双周、指定周次和下一门课，也会影响课程通知、每日推送、小组件及日历同步。这里的「第几周」是学期教学周，不是系统日历中的全年周数。

设置后检查当前周次。如果和学校课表不同，先调整学期日期，再添加或导入课程。

### 手动添加课程

在 **课程表** 的右上角菜单选择 **手动添加课程**，填写：

- **课程名称**：必填，建议与学校课表一致。
- **教室或地点**：用于课程展示和通知。
- **教师**：选填。
- **星期、开始时间、结束时间**：结束时间必须晚于开始时间。
- **周数模式**：每周、单周或双周，并设置起止教学周。
- **指定具体周次**：不规则排课可直接填写，例如 `1,2,4,7`。
- **提前提醒时间**：控制这门课的课前预警时间。
- **课程颜色**：方便在课表中区分课程。

跨午夜的课程不能作为同一天的一条课程填写。如果学校给出的排课包含这种情况，需要自行拆分并核对日期。

例如：周二 10:00—11:40、第 1—16 周的双周课程，只会在对应的偶数教学周参与提醒和课程判断。

### 查看、修改与停用

课表可以切换教学周，也可以查看 **全学期总表**。查看其他周只是改变当前浏览内容，不会把系统通知切换成那一周的日期；查看后可以选择 **回到本周**。

通过右上角 **课程管理** 可以搜索课程名称、教师或教室，查看并修改同名课程的不同安排。删除前确认自己选中的是某条安排还是整组课程。

课程表单中的 **启用课程提醒** 同时决定课程是否参与当前有效课程的计算。关闭后，这门课会退出下一课、提醒、每日课程统计及日历同步的计算。仅想关闭所有课前通知时，应使用设置页的全局课前开关。

## 5. 导入 .ics 课表

`.ics` 是日历文件。应先从学校课表系统或其他日历工具导出文件，再交给千语导入。课程截图、PDF 和聊天中的图片不能直接作为课表导入。

### 导入步骤

1. 在课程表菜单选择 **导入 .ics 日历课表**，选择文件。
2. iPhone 也可以在「文件」或附件的分享菜单中选择千语；部分系统界面可能显示英文名 **QIAN YU**。
3. 检查导入预览中的名称、星期、时间、地点和周次，勾选需要导入的课程。
4. 选择导入方式，确认后保存。

打开预览不会直接写入课表，只有确认导入才会保存。

| 导入方式 | 作用 |
| --- | --- |
| 追加到现有课表 | 保留已有课程，加入所选课程；符合合并条件的安排会合并周次或补充信息 |
| 清空并覆盖现有课表 | 删除应用内现有课表，再导入本次选择的课程 |

同名、同星期、同时间，并且教室及教师信息相容的课程可以合并。因此重复追加同一份文件通常不会增加一整套重复课程，但来源信息变化时仍应检查导入结果。

若预览提供 **自动校准开学日期**，先与学校教学周核对，再决定是否使用。文件中的日期不一定能准确代表学校的第一教学周。

不同工具导出的重复规则可能不同。全天事件或无法转换为课程的复杂事件可能不会导入，预览和导入提示应作为最后的核对依据。建议保留原始 `.ics` 文件，便于以后重新导入。

## 6. 同步到 Apple 日历

在课程表菜单中选择 **同步至 Apple 系统日历**，根据提示允许日历访问。千语需要读取并管理自己创建的事件，因此需要相应的完整日历访问权限。

同步后，打开系统「日历」，找到 **QIAN YU 课表**。千语会根据教学周生成实际日期上的课程事件，包含课程时间、地点和相关说明。

这是手动的单向同步：

- 在千语中修改课表后，需要再次点击同步，系统日历才会更新。
- 在系统日历中修改事件，不会反向修改千语里的课程。
- 再次同步会重建千语标记的课程事件，正常情况下不会叠加同一批事件。
- 停用课程不会继续导出；已经导出的旧安排会在下次同步时更新。

如果同时开启千语的课前通知和日历事件提醒，可能收到两次提醒。可以按自己的习惯关闭其中一处的提醒。

不想继续显示课表时，可在系统日历中取消勾选 **QIAN YU 课表**。删除整个日历会连带删除其中的事件，包括你自己放入该日历的内容，因此隐藏和删除的效果不同。

## 7. 课前与课后提醒

进入 **设置 → 每日提醒与上课通知 → 上课提醒与学期教学周**：

- **启用课前千语智能通知**：按照各门课的提前提醒时间，提示课程、教室和上课时间。
- **启用课后千语收尾关怀**：在下课时提醒收拾物品、喝水活动，并结合接下来的课程安排提示。

课程必须在对应教学周有效，并处于启用状态，才会参与通知排程。修改时间、周次或学期日期后，打开应用核对课表和提醒设置。

系统允许排队的本地通知数量有限。课程较多时，应用优先安排近期通知，并在后续打开应用或系统允许刷新时续排；不会一次性把整个学期的所有通知全部放入系统队列。

## 8. 每日推送的时间规则

入口是 **设置 → 每日提醒与上课通知**。下面是全新安装、尚未自行修改设置时的默认值；旧版本升级会保留已经保存的时间。

| 提醒 | 默认时间 | 实际发送规则 |
| --- | --- | --- |
| 清晨唤醒 | 07:45 | 未启用睡眠自动化时按设定时间；启用后优先跟随早晨的睡眠结束动作，最迟在设定时间后 1 小时发送 |
| 午饭提醒 | 12:00 | 有上午课时按上午最后一节课的结束时间判断；没有上午课时按设定时间 |
| 午后防困 | 13:45 | 仅在当天 14:00—15:00 与有效课程有重叠时发送 |
| 傍晚鼓励 | 18:00 | 按设定时间发送，内容根据那时是否还有课调整 |
| 深夜就寝 | 22:30 | 未启用睡眠自动化时按设定时间；启用后优先跟随睡眠开始动作，最迟在设定时间发送 |

每类提醒可以单独开关，也可以修改时间。

### 午饭时间如何计算

应用把 **开始时间早于 12:00 的课程** 作为上午课程，取其中最后的结束时间：

- 早于 11:00 结束：11:30 提醒。
- 11:00 或之后结束：在下课时间提醒。
- 没有上午课程：使用你填写的午饭时间。

例如，最后一节上午课 10:40 结束，午饭提醒在 11:30；11:00 结束，提醒就在 11:00；11:50 结束，提醒就在 11:50。10:00 开始、12:20 结束的课也属于这项规则中的上午课程。

### 午后提醒为什么有时不出现

它只在 14:00—15:00 有课时发送。例如 14:20—15:40 的课程满足条件；一门课恰好在 14:00 结束，或恰好在 15:00 开始，本身不算与该时段重叠。

13:45 是提醒时间，14:00—15:00 是判断是否需要提醒的课程时段。更改提醒时间不会改变这个判断时段。旧用户如果仍显示 14:00，可以在设置页手动改成 13:45。

### 睡眠联动的截止时间

以清晨设为 07:45、就寝设为 22:30 为例：

- 07:10 运行「睡眠已结束」：优先发送早安。
- 08:10 运行「睡眠已结束」：仍可优先发送早安。
- 直到 08:45 都没有运行早晨动作：发送预先安排的早安。
- 21:50 运行「准备睡觉」：优先发送晚安。
- 到 22:30 都没有运行就寝动作：发送预先安排的晚安。

截止后运行动作，不会为了这次提醒再补发一条。早晨动作只在上午处理，早晚各自每天只处理一次；跨午夜的就寝时间也按对应的就寝周期判断。

### 普通通知与续排

当前版本使用**普通本地通知**。横幅、声音、通知摘要和专注模式中的显示，都遵循你的系统设置。「即时通知」能力没有启用，以保留免费 Personal Team 的编译安装方式。

每日提醒预排未来 7 天，打开应用、执行睡眠动作以及系统允许的后台刷新会尝试续排。如果很久不打开应用，睡眠自动化也没有运行，后续提醒可能中断。建议平时查看课表时顺便打开千语；后台刷新不能保证每天执行。

## 9. 配置睡眠自动化

千语不会自己识别手机何时进入或退出「睡眠」专注模式。需要由 iPhone 的快捷指令把相应事件传给千语。

### 早晨自动化

1. 打开 iPhone 的 **快捷指令 → 自动化**，新增个人自动化。
2. 如果触发器允许选择「睡眠」专注模式，选择它的 **关闭时**。
3. 将自动化设置为 **立即运行**，避免每次都需要手动确认。
4. 添加千语的 **睡眠已结束** 动作，保存自动化。

### 就寝自动化

1. 再新增一项自动化。
2. 选择「睡眠」专注模式的 **开启时**。
3. 设置为 **立即运行**。
4. 添加千语的 **准备睡觉** 动作，保存。

两项都配置完成后，回到千语的推送设置页，开启 **已配置睡眠自动化**。仅打开这个开关，不会自动创建快捷指令。

### 如果系统里的选项不同

不同 iOS 版本和系统配置显示的触发器可能不同。Apple 的[设置触发器说明](https://support.apple.com/guide/shortcuts/setting-triggers-apde31e9638b/ios)列出了专注模式开启和关闭事件；但快捷指令中另一个「睡眠」触发器可能只有「助眠开始」「就寝时间开始」「起床」等选项。

后者依赖健康 App 的睡眠计划，其中「起床」对应计划中的唤醒闹钟，并不等同于任意一次手动关闭睡眠专注模式。详见 [Apple 睡眠事件触发器说明](https://support.apple.com/guide/shortcuts/event-triggers-apd932ff833f/ios)。

如果只有睡眠计划事件，可以把合适的起床事件接到「睡眠已结束」、就寝事件接到「准备睡觉」，让通知跟随计划。若你需要跟随手动切换，而系统没有提供对应事件，应暂时关闭 **已配置睡眠自动化**，使用固定时间提醒。

### 动作找不到或没有执行

先确认安装的是包含这两个动作的版本，并至少打开过一次千语。添加动作时可搜索「千语」「QIAN YU」或动作名称。检查自动化是否启用、是否需要确认、实际选择的是哪个触发器。

睡眠动作提前发出通知时，通知仍是普通通知。若当时处于专注模式，是否显示横幅取决于系统对千语的通知许可。

## 10. 天气与常用地点

天气设置位于每日推送页面，用于早晨问候。默认常用地点是 **深圳市南山区**，首次使用建议改为自己的城市或区。

### 手动选择城市和区

1. 在 **常用城市 / 区** 输入框填写地名，例如「深圳市南山区」。
2. 点击 **查找城市与区**。
3. 在搜索结果中选择正确的地点。
4. 检查页面显示的常用地点。

只输入文字还没有完成地点选择，需要点击搜索结果才会保存。尽量写完整的城市和区，避免同名地名带来误差。

### 使用当前位置

点击 **使用当前位置**，根据系统提示允许使用期间定位。应用会获取一次位置；可以打开 **优先使用已获取的当前位置**，让近期获取的位置优先于常用城市。

这不是持续后台定位。换了城市后，可以再次点击按钮更新位置。定位被拒绝、权限被撤销或位置超过一天未更新时，会使用你保存的常用城市。

天气来自 Open-Meteo，使用通知对应日期的预报，包括天气概况、温度范围和降雨概率等信息。预报会提前获取并缓存，因此不等同于推送那一刻的实时观测。无法取得可靠天气时，问候会省略天气内容，不影响其他提醒。

## 11. 配置 AI 服务

入口是 **设置 → AI 模型驱动（OpenAI 协议兼容）**。这里的「OpenAI 协议兼容」指接口格式，实际模型和费用由你选择的服务商决定。

### 配置顺序

1. 在 **服务商预设** 中选择服务商。
2. 核对 **接口地址**，按照服务商的文档填写兼容接口地址。
3. 填写自己的 **API Key**。密钥输入框的眼睛按钮可切换显示或隐藏。
4. 点击 **刷新模型列表**，在 **选择模型** 中选一个可用模型；也可直接填写完整 **模型 ID**。
5. 如果模型支持，在 **思考强度** 中选择合适档位；不确定时使用自动设置。
6. 点击 **测试当前配置**，等待测试结果。
7. 回到陪伴页发一条短消息，确认实际回复正常。

模型 ID 必须与服务商要求的名称一致。部分接口不提供模型列表，这时需要手动填写；列表中出现模型，也不代表你的账户已经有调用额度或权限。

**已保存**表示配置已保存，**连接测试通过**表示当前配置实际通过了一次请求测试。修改地址、密钥或模型后，应该重新测试。

每个服务商分别保存接口、模型、思考设置和密钥。切换服务商后，检查当前显示的是不是你想使用的配置。

### 模型、测试状态与思考设置怎么用

手动填写模型 ID 后会保存，重新启动不需要再次从列表选择。刷新列表失败时，保留服务商文档给出的完整 ID，再测试实际调用；模型名称或套餐不同，不能仅凭展示名称猜测 ID。

**自动**表示不发送额外思考参数，使用服务端默认行为，并不表示关闭思考。应用按接口地址和模型识别支持的参数，具体映射显示在思考选择框下方：

- 支持同名 `reasoning_effort` 的模型，按所选档位传递。
- 支持思考开关的模型，使用开启或关闭参数，不把开关虚构成低、中、高强度。
- 未识别或未确认支持的模型，保留服务端默认值；自定义中转地址可能无法沿用官方地址的识别结果。

修改接口、密钥、模型或思考设置后重新点击 **测试当前配置**。测试通过只说明这组配置当时可以请求，不保证以后仍有额度或网络始终可用。测试错误时保留完整错误文字，按第 17 章排查；不要在反馈中提供密钥。

### 本地 Ollama

Mac 上可使用本机 Ollama 的 OpenAI 兼容接口。服务器没有设置密钥认证时，可以不填 API Key，但仍要填写实际提供的模型 ID。

在 iPhone 上，`localhost` 指的是 iPhone 自己，不是 Mac。要访问 Mac 上的服务，需要手机能访问 Mac 的局域网地址，且本地服务允许对应连接。先确认网络可达，再在千语中测试；不要把只供自己使用的无认证接口直接暴露到公网。

## 12. AI 每日问候

在每日推送页打开 **用 AI 生成每日问候**。它沿用设置中的接口和模型，自动生成可能产生 API 费用，不需要为每日推送再配置一套密钥。

| 场景 | 文案参考信息 |
| --- | --- |
| 早晨 | 对应日期的天气预报，温度及降雨等日常提示 |
| 中午 | 当天课程数量和上课总时长，安排较满时给予鼓励，较轻松时温和提醒吃饭 |
| 午后 | 即将到来的 14:00—15:00 课程，提醒喝水、活动肩颈 |
| 傍晚 | 提醒时刻是否还有课程，有课时鼓励继续完成剩余安排，没有后续课时轻松收尾 |
| 就寝 | 简短、自然的晚安 |

课程时长根据课表统计，间隔不算上课时间，重叠时段不会重复累计。文案知道的是排课安排，不知道你是否真的到课、是否完成作业，或是否已经吃饭。

应用会检查正文重复。内容可以表达相近的关心，但生成结果如果与已有正文相同，或只改标点和表情，会被拒绝并使用本地备选文案。无 API、网络失败或模型返回格式不符合要求时，也会使用可变的本地文案。

文案通常在打开应用或系统允许刷新时提前生成并缓存，通知到点不会临时等待 AI 请求。因此它不会知道生成之后临时发生的所有变化，也不能保证每条通知都来自实时生成。

自动问候使用模型支持的轻量思考设置，减少这类短文本任务的开销。想停止自动 AI 调用，可以关闭 **用 AI 生成每日问候**；普通提醒和本地问候仍可使用。

## 13. 聊天与角色设定

在陪伴页输入文字发送，或点击快捷话题开始对话。配置了可用的 AI 后，回复会逐步显示；没有可用配置时，使用内置台词。

对话会结合称呼、时间、已保存的学期课表和近期消息。它不会每次把全部历史聊天都交给模型，也不保证记住很久以前的内容。当前聊天支持文字，不支持直接识别你发送的图片、语音或附件；`.ics` 导入应使用课程表入口。

聊天记录会保存，正常退出后重新打开仍可查看。陪伴页菜单中的 **清空对话记录** 会删除记录，操作前确认自己不再需要这些内容。

### 询问课表

先在课程表中保存课程，并设置正确的第一教学周日期，再输入问题。例如：

- 「这个学期都有什么课？」：查看学期课程与排课背景。
- 「今天还有什么课？」或「下一节什么课？」：查看当天剩余安排。
- 「明天有什么课？」或「下周一有什么课？」：按对应日期的教学周和课程周次判断。

千语读取的是应用内已保存的课表，不会自动登录学校系统获取最新调整，也不知道你是否实际到课。课程取消、换教室或调课时，先在课表中修改；准确时间和地点仍可在课程表核对。未导入课程时，应先导入或添加，聊天不能代替建立课表。

### 等待回复、停止与重试

发送后，右侧发送按钮会变成停止按钮。点击它可以停止当前生成并保留已收到的文字。网络或接口报错时，已收到的部分仍会显示，可以点击 **重试回复** 再次请求；重试可能再次消耗模型额度。

等待回复时可以切到应用内的其他页面，再返回继续查看。把应用放到后台或锁屏后，iOS 可能暂停应用和网络任务，不能保证长回复持续生成；需要完整回复时，尽量保持应用在前台。

### 查看历史和复制内容

往期聊天默认折叠，点击 **展开往期历史记录** 查看，需要更早内容时点击 **加载更早的消息**。向上阅读时不会持续跟随新回复跳到底部，点击 **回到最新消息** 可以继续跟随。

长按消息气泡（Mac 上右键）选择 **复制**。如果页面提示保存失败，点击 **重试保存**；在保存成功前不要把当前内容当作已经可靠落盘的记录。

### 修改角色设定

进入 **设置 → 关于应用 → 角色人设**：

1. 默认使用项目中的完整原版人设；编辑人设文本，可以调整身份、语气、回复长度和对话习惯。
2. 点击 **保存**。
3. 从下一条 AI 对话开始使用新的设定。

点击 **恢复默认** 只是把默认内容填回编辑框，还需要点击 **保存**。离线固定台词仍使用内置语料；每日问候另有任务规则和备选文案，不能把修改人设视作对所有界面文字的统一修改。

如需让表达更自然，可以在设定中允许符合性格的比喻、假设和轻度想象，同时区分想象与事实。模型回复不是角色官方资料，涉及原作经历时仍应自行核对。

## 14. 专注番茄钟

打开专注页，选择模式和时长：

| 模式 | 可选时长 |
| --- | --- |
| 专注 | 15、25、45、60 分钟 |
| 小憩 | 5、10、15 分钟 |

点击 **开始专注** 或 **开始小憩** 开始倒计时。计时中可以暂停、继续或重置；结束后可以 **再来一轮**。切换模式会重置当前计时，开始前先选好模式。

切换标签或把应用放到后台，不会把计时当作暂停。应用根据预定结束时间计算剩余时长，并保存计时状态；重新打开时会恢复相应状态或显示已经结束。

允许通知后，可以接收完成提醒。iPhone 上还可通过锁屏实时活动查看进度；支持灵动岛的设备可显示对应活动。专注结束后若想休息，需要自行选择小憩并开始，当前不自动接续一整套专注与休息循环。

## 15. 小组件、实时活动与 Mac 菜单栏

### 添加课程小组件

在 iPhone 主屏幕的编辑界面选择添加小组件，搜索千语或 **QIAN YU**，选择合适样式后添加。支持的锁屏也可以在锁屏自定界面添加相应小组件；Mac 可在系统的小组件选择器中查找。

课程小组件显示当前教学周和接下来的课程。当天没有后续课程时，显示无课或课程已结束的状态，这不表示整个学期都没有课。

小组件依赖系统刷新，不会每秒更新。修改课表后先打开一次千语；如果仍不一致，检查学期日期、当前教学周和课程是否启用。

### 实时活动与灵动岛

开始番茄钟后，可查看锁屏上的计时活动。在支持灵动岛的 iPhone 上，还能查看灵动岛中的进度。若没有出现，检查系统是否允许千语使用实时活动。

专注页面与专注实时活动使用专注头像；普通聊天仍使用原来的千语头像，两者不同是预期效果。

应用设置中的 **小组件与灵动岛全览** 可用于查看相关展示效果。系统、机型和权限会影响实际显示，预览不代表所有设备都支持同一种布局。

### Mac 菜单栏

Mac 运行千语时，顶部菜单栏会出现千语入口。点击后可以查看状态、下一门课程倒计时，也可以使用迷你聊天。

菜单栏聊天使用同一套 AI 配置。关闭窗口与完全退出应用是不同操作；完全退出后，菜单栏入口也会关闭。

## 16. 权限、数据与费用

### 按功能授予权限

| 权限 | 用途 | 不授权时 |
| --- | --- | --- |
| 通知 | 每日问候、课前课后通知、计时完成提醒 | 可以继续查看课表和使用计时，但收不到相应系统通知 |
| 日历完整访问 | 管理千语导出的课程事件，并更新旧事件 | 应用内课表仍可使用，系统日历同步不可用 |
| 使用期间定位 | 点击按钮获取地点，用于天气 | 可以手动选择常用城市和区 |
| 实时活动 | iPhone 锁屏和灵动岛计时展示 | 应用内番茄钟仍可使用 |

这些权限不需要一开始全部授予，按自己要使用的功能选择即可。之后可以在系统设置中调整。

### 数据保存与外部请求

聊天和课表会保存在应用的数据存储中；个人偏好会保存，API Key 使用系统钥匙串保存。不要把这些理解为已经具备完整的跨设备同步或云端备份。当前提供手动备份与恢复，范围见下文；它不包含全部偏好或任何 API Key。

### 导出备份与恢复

入口：**设置 → 关于应用 → 备份与恢复**。

1. 点击 **导出备份**，选择保存位置，保存生成的 JSON 文件。备份包含课程、聊天、人设、称呼和学期起始日。
2. 在新安装或另一台设备上打开同一入口，点击 **恢复备份**，选择此前导出的 JSON 文件。
3. 等待 **备份已恢复** 提示，再检查课表、历史聊天、称呼、人设和学期日期。
4. 重新检查通知权限及提醒设置；需要 AI 时另行填写并测试接口、模型和 API Key。

恢复会按记录标识合并缺少的课程和消息，保留当前已有记录；**人设、称呼和学期起始日会使用备份中的值**。它不用于撤销现有记录的编辑或把所有设置恢复到某一时刻。恢复前可以先导出当前备份，避免丢失仍需要的设定。

备份不包含 API Key、服务商配置、通知与天气等全部偏好，也不包含系统日历事件。文件不能超过 50 MB，必须是千语生成且格式受支持的备份。不同来源课表中的相同课程若有不同记录标识，恢复后仍可能重复，请在课程管理中核对。

JSON 文件中包含可阅读的聊天内容，应存放在自己信任的位置。导出是手动操作，不会自动每天生成新备份；原始 `.ics` 只能用于重新导入课程。

### 外部请求

不同功能会向不同服务发送必要信息：

- **AI 聊天**：向你配置的接口发送近期对话、角色设定及相关时间和课程背景。
- **AI 每日问候**：发送天气概况、课程统计、称呼、角色设定和近期通知正文，不发送聊天记录、精确坐标或街道地址。
- **地点查询**：使用 Apple 地理编码服务查询或识别地名。
- **天气查询**：向 Open-Meteo 发送所选地点的坐标，获取预报。

AI 服务的数据处理方式取决于你选用的服务商。截图、反馈或分享配置时，不要把 API Key 发给别人。

原始 `.ics` 文件可以用于重新导入课程，但不能作为聊天和全部设置的备份。删除 App、清理数据或改变应用标识前，应先保留自己仍需要的内容。

### 可能产生的费用

AI 聊天、连接测试和自动生成每日问候都可能消耗服务商额度。是否收费、收费多少，以服务商的账户和账单为准。源码可获取，不代表第三方模型调用免费。

## 17. 常见问题

### 为什么没收到通知？

先点击 **发送测试通知**，等待约 3 秒，再检查通知中心。如果测试也没有收到，检查系统是否允许千语通知，是否关闭了横幅或声音，以及专注模式或通知摘要是否影响显示。

测试正常但某一条提醒没有出现时，再检查该提醒开关、课程有效周次、学期日期和时间规则。午后无课时本来就不会发送；睡眠动作超过截止时间也不会补发。长期没有打开应用时，先打开一次让它续排。

### 改了午饭时间，为什么还是下课后推送？

有上午课时，下课规则优先。设置的午饭时间用于没有上午课的当天。

### 为什么我设置了 13:45，今天没有午后提醒？

只有 14:00—15:00 与有效课程重叠才会发送。检查的是课程时段，而不是你是否启用了 AI。

### 开了睡眠自动化开关，为什么没有跟随睡眠？

应用内开关不会创建自动化。检查快捷指令中的两项自动化是否存在、启用并设置为立即运行，以及动作名称是否正确。还要区分「专注模式切换」和「健康睡眠计划事件」。

### 天气一直显示深圳南山，或换城市后没有变化？

先查找并点击保存自己的城市或区；只改输入框文字不算完成。若优先使用已获取的位置，则可以重新获取当前位置，或关闭这个优先开关。天气与通知文案有缓存，修改地点后不会改写已经送达的通知。

### 为什么每天的问候还是有些相似？

问候围绕固定的日常场景，意思相近是正常的。应用检查的是正文重复，不保证每次都采用全新话题。检查 AI 开关和连接测试；网络或生成失败时会使用本地备选文案。

### AI 无法回复，应该检查什么？

依次核对接口地址、API Key、完整模型 ID、网络、账户额度和模型权限，然后点击 **测试当前配置**。如果模型列表无法刷新，可以按服务商文档手动填写模型 ID。iPhone 访问 Mac 上的模型时，不要把 Mac 的地址写成手机的 `localhost`。

### 返回「内容不是有效 JSON」怎么办？

这不一定表示 API Key 错误，也可能是接口地址返回网页、代理错误或服务返回格式与接口协议不一致。先核对兼容接口地址和完整模型 ID，再测试当前配置；如果只在特定网络发生，换网络重试。反馈时提供所选服务商、接口地址、模型 ID 和完整错误文字，遮住 API Key。不要为了排查把密钥放进公开链接。

### 聊天回答不知道我的课表怎么办？

确认课程已经保存、处于启用状态，学期日期和指定周次正确；试问「这个学期都有什么课？」并与全学期总表对照。模型可能受到自己修改的人设影响，不应在人设中要求忽略课表或虚构安排。仍异常时保留问题和错误回复供反馈。

### iPhone 在切换页面或聊天时发热怎么办？

优先使用 Release 构建观察：通过 Xcode 调试运行时的额外开销可能影响表现，侧载下载页提供 Release 包。长回复可以点击停止，日常问答可使用模型支持的较轻思考档位。应用已减少逐字刷新和重复动画，并在低电量或较高温度时降低聊天显示刷新频率；API 模型通常在服务端运行，选择高思考档位也可能让等待时间更长。持续明显发热时，反馈系统版本、构建、是否在调试运行以及触发操作。

### 恢复备份后为什么 AI 不能用，或旧课程没有被改回去？

备份不包含 API Key 和服务商配置，需要重新配置并测试。恢复合并缺少的课程和消息，不覆盖已经存在的同一条记录。称呼、人设和学期起始日会替换为备份值；检查这些字段后再核对课程。

### Mac 弹出访问 API 密钥的登录密码请求怎么办？

先确认提示来自千语的系统钥匙串访问，使用自己的 Mac 登录密码处理。旧构建或签名身份变化可能影响钥匙串访问；反复出现时，退出应用，使用同一签名配置重新构建，并在设置页检查密钥保存或迁移状态。不要在聊天或问题反馈中提供登录密码或 API Key。

### 课表、小组件和通知的周次不一致？

先核对开学第一周日期，再回到本周查看。浏览某个指定周不会改变通知采用的实际教学周。小组件可能稍晚刷新，打开应用后再观察。

### Apple 日历里为什么还是旧课表，或有两次提醒？

修改千语课表后，需要再次手动同步。两次提醒可能分别来自千语和 Apple 日历，检查两边的提醒设置。重复事件还可能来自你自己另行导入的日历；千语只管理自己标记的同步事件。

### 免费账户安装后，过几天 App 打不开？

可能是 Personal Team 的安装签名到期。连接设备，通过 Xcode 用相同应用标识重新编译安装。不要先卸载应用作为常规续签步骤。

### Xcode 中修改文字会立刻出现在 App 吗？

源码文件会按编辑器设置保存，但保存与运行更新是两件事。正在运行或已经安装的 App 不会因为文件保存自动变成新版本，需要重新编译安装。若只想维护显示文字，可另看仓库中的 `文案维护.md`。

```bash
bash Scripts/check_project.sh --checks-only
```

```bash
bash Scripts/check_project.sh --build-only
```

```bash
bash Scripts/check_project.sh --output-dir /tmp/qianyu-validation
```

### 二、GitHub Actions

`.github/workflows/validate.yml` 在以下事件执行同一入口：

- 向 `main` 推送提交。
- 推送以 `v` 开头的标签。
- 创建或更新 PR。
- 在 Actions 页面手动运行。

工作流只需要读取仓库，检出时不保留凭证，也不需要配置 API 密钥或 Apple 签名证书。日志会作为附件保留 14 天；构建产物不会作为可安装版本发布。

目前选择 `macos-15` 和 Xcode 26.3。升级工具链时检查 [GitHub 托管 macOS 镜像的 Xcode 列表](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md)，确认镜像中存在对应路径，再修改 `DEVELOPER_DIR`。不要只依赖运行器的默认 Xcode。

本地执行通过不等于 GitHub 上已经执行通过。工作流推送后，应在 Actions 页面检查对应提交的结果。

### 三、课程时间规则

`CourseTimeRules.swift` 只依赖 Foundation，集中处理：

- 周一为起点的教学周和课程星期编号。
- 开学前的实际教学周与界面显示周次。
- 指定周次优先于起止周和单双周规则。
- 课程实际日期、分钟时间和时间重叠。
- 按教学周及日期筛选有效课程。

`CourseScheduleRule` 是不可变的课程规则输入。通知和每日问候使用它，小组件使用相同的时间函数；主应用保存的 `CourseItem` 和小组件快照格式继续保留。

**开学前显示第 1 周不代表第 1 周课程已生效。** 查询实际课程使用 `teachingWeek`，界面标签使用 `displayWeek`。新增任何依赖周次的功能，都应明确选择其中一个。

以下边界保留现有约定：

- 两门课首尾相接不算时间重叠。
- 下一课界面保留课程结束的那一分钟；下一分钟才移除。
- 每日问候的剩余时长只计算提醒时刻之后的时间。
- 晨间兜底可以因延后一小时跨过午夜。

新的日期计算应传入 `Calendar` 和日期进行检查，避免通过修改系统时间测试。新增周次规则时，同时核对课表、通知、日历和小组件。

### 四、通知职责

```text
课表变化 / 设置变化 / 前台激活 / 后台刷新
                    ↓
          NotificationManager.reschedule
                    ↓
     每日请求 + CourseReminderService 课程请求
                    ↓
           NotificationScheduler
                    ↓
       NotificationRequestStore → 系统通知中心
```

`NotificationManager` 协调每日计划、睡眠动作和 AI 文案更新。`CourseReminderService` 负责生成课前、课后请求，公开的同步入口继续转交统一排程。

`NotificationScheduler` 管理异步写入队列及 64 个待处理请求的容量，优先保留每日通知，再安排近期课程通知。它只替换 `qianyu_daily_` 与 `qianyu_course_` 开头的请求，保留番茄钟和测试通知占用的名额。

`NotificationRequestStore` 将系统读写隔离出来，专项检查可用内存实现。睡眠通知和 AI 更新也经统一队列执行。AI 返回后仍需核对待发送请求的日期及发送状态，避免旧内容重新加入已经替换或送达的通知。

新增通知类型时，需要确定标识前缀、所有者及容量策略；不要在视图里自行清空应用的全部待处理通知。操作队列的内部方法不应再等待当前队列自身，以免造成循环等待。

### 五、ICS 导入流程

| 文件 | 职责 |
| --- | --- |
| `ICSParserService.swift` | 保留公开解析入口，收集事件、应用调课例外，并组合结果 |
| `ICSImportModels.swift` | 解析草稿、结果和错误类型 |
| `ICSFileDecoder.swift` | 编码尝试、折叠行、转义、日期和时长解析 |
| `ICSSemesterDetector.swift` | 从学校元数据或事件信息推测学期起点 |
| `ICSRecurrenceParser.swift` | 精确周次、周重复、COUNT、UNTIL、BYDAY 和 EXDATE |
| `ICSCourseConverter.swift` | 从事件生成课程、提取名称地点教师、去重和配色 |

外部代码继续调用 `ICSParserService.shared.parse`。可以传入 `fallbackSemesterStartDate`，在文件没有学期元数据时提供确定的参考日期；未传入时沿用应用设置。文件检测出的学期日期仍优先。

添加新的导出格式兼容时，应把样例整理成不含个人信息的小型文件或字符串，加入导入检查。修改重复规则时，至少检查 COUNT、UNTIL、多个 BYDAY、EXDATE 和 RECURRENCE-ID，不能只验证单次事件能被读取。

### 六、发布前核对

### 聊天与性能验收

聊天流式文本正常每 100 毫秒合并一次刷新；低电量或系统报告严重发热时改为 250 毫秒，聊天页不可见时改为 500 毫秒。返回页面、停止和生成结束时立即补齐缓存。正文与思考文本一起合并，保存检查点间隔为 5 秒，切页和应用进入非活跃状态时也保存。离线回复同样按可见性降低更新频率。

历史记录每次读取 40 条；当前会话保持普通布局以避免切页后空白。阅读旧消息时停止自动跟随，使用“回到最新消息”恢复。逐片段震动与专注页持续光晕动画已移除，番茄钟每秒核对绝对截止时间。

在 iPhone Air 上安装同一提交的 Release 配置，停止 Xcode 调试连接后，对比相同模型、回复长度与切页操作。检查生成中切页再返回、上滑阅读时继续生成、停止与重试、离线回复和展开历史。需要测量时使用 Instruments 的 Time Profiler 与能耗分析，关注主线程文本布局、滚动和唤醒；模拟接口的刷新次数检查不能证明真机温度下降。

设置中的“备份与恢复”导出 JSON，包含课表、聊天、人设、称呼和学期起始日，不含 API Key。恢复按 UUID 合并已有记录，不删除当前数据；称呼、人设和学期起点使用备份值。恢复后核对课表、聊天和通知排程。

### 发布清单

1. 完整运行统一入口，检查汇总和失败日志。
2. 确认 GitHub Actions 对准备发布的提交通过。
3. 真机核对通知、睡眠自动化、定位拒绝与城市回退、日历重复同步、实时活动和小组件。
4. 真实 AI 接口检查需要自备密钥；不要将密钥写入样例、日志或提交。
5. 只有构建与模拟检查通过时，在发布说明中列明尚未完成的真机项目。

未签名构建只验证编译，模拟通知存储只验证排程行为，都不能替代系统权限和实际通知送达的验收。

### 打包与分发

先运行 `bash Scripts/check_project.sh`，再运行：

```sh
bash Scripts/package_macos.sh
```

默认输出到被 Git 忽略的 `build/distribution/`，包含 ZIP、SHA256SUMS.txt 和构建日志。可用第一个参数指定输出目录。脚本从当前源码构建，不包含个人 API Key、课表文件或聊天数据库。

iPhone 侧载包使用 `bash Scripts/package_ios.sh`，输出到 `build/ios-sideload/`。它构建设备 arm64 Release，启用 `QIANYU_SIDELOAD` 使用应用内的本地数据库，保留扩展，以本地签名附带可供 SideStore 读取的能力声明。安装仍必须通过 SideStore 的个人账号重新签名。输出 IPA、源索引、构建信息及 SHA-256 校验文件。

`.github/workflows/ios-sideload.yml` 在 main 的相关文件更新或手动运行时执行回归检查和打包，并更新独立的 `ios-sideload` 预发布频道，不改动版本发布标签。该频道的标签始终指向当前成功发布的源码，资产和源索引一起更新；构建发布只使用仓库发布令牌，不包含个人签名凭据。SideStore 安装能力和续签仍由设备与个人账号决定。

脚本仅为 Mac 分发构建启用 `QIANYU_LOCAL_DISTRIBUTION`，将密钥存储切换到独立的登录钥匙串项目。普通 Xcode 构建和 iPhone 构建继续使用原有存储方式。

# 千语安装与分发

千语支持 iOS 17 及以上、macOS 14 及以上。安装应用不包含 AI 服务费用，API 由用户自行配置。iPhone 支持 SideStore IPA 安装与源码自签，Mac 使用本地签名包。

## iPhone：使用免费 Apple 账号自签

需要一台 Mac、Xcode、自己的 Apple 账号和一台 iPhone。普通 Apple 账号即可，不需要购买 Apple Developer Program。

1. 从仓库或 GitHub Release 下载源码并解压，用 Xcode 打开 `QIAN YU.xcodeproj`。
2. 在 Xcode 的 Settings → Accounts 中登录自己的 Apple 账号。
3. 点击左侧工程，分别选择 `QIAN YU` 和 `QianYuWidgets` 两个 target。在 Signing & Capabilities 中开启 Automatically manage signing，将 Team 改为自己的 Personal Team。不要保留作者的 Team。
4. 如提示 Bundle Identifier 不可用，将两者分别改为自己的唯一标识，例如 `com.yourname.qianyu` 和 `com.yourname.qianyu.widgets`，保持扩展标识以主应用标识开头。
5. 若 Xcode 要求更换 App Group，在两个 target 中使用同一个可用组，同时替换两份 entitlements、`CourseScheduleViewModel.swift` 和 `QianYuCourseWidget.swift` 中的 `group.com.qianyu.companion`。不要只改一处，否则小组件读不到课表。免费团队能否使用相关能力以 Xcode 的签名结果为准。
6. 连接并解锁 iPhone，确认“信任此电脑”。在手机「设置 → 隐私与安全性」中开启开发者模式，按系统提示重启并确认。
7. 在 Xcode 顶部选择自己的 iPhone，按 `Cmd + R` 安装。若系统要求信任开发者，在「设置 → 通用 → VPN 与设备管理」中确认。
8. 打开千语，允许通知；按需导入课程、设置 API 和睡眠快捷指令。

免费签名的描述文件有效期为 7 天。到期后连接手机，用同一账号、相同标识重新运行即可。更新前不要删除应用，以免丢失本地课表和聊天记录；重要课表应保留原始文件。使用同一签名身份更新后仍需确认数据保留情况。

Apple 的免费账号用于个人设备测试，并非 App Store 分发资格。签名能力或配额不足时，先按照 Xcode 的具体错误排查，不要购买来历不明的共享证书。

参考：[Apple 免费账号与限制](https://developer.apple.com/help/account/basics/about-your-developer-account/)。

### IPA 侧载

项目提供用于重新签名的 IPA 构建产物，下载和检查范围见 [iPhone 安装指南](iPhone免费安装.md)。IPA 不是 App Store 安装包，安装与续签要求由所用工具和账号决定；包结构检查不能替代真机验收。现有 Mac 下载包不能安装到 iPhone。

## Mac：安装本地签名包

下载包名称为 `QIAN-YU-macOS-universal-local.zip`，同时包含 Apple Silicon 与 Intel 架构。只有 Release 明确列出该资产时才代表已提供下载；源码压缩包不是应用。

1. 下载并解压，将 `QIAN YU.app` 拖入「应用程序」。
2. 第一次打开可能提示无法验证开发者。确认包来自本项目后，在「系统设置 → 隐私与安全性」中选择“仍要打开”，按系统要求再次确认。
3. 本地签名包使用 macOS 登录钥匙串保存 API Key，与 Xcode 版本的受保护钥匙串分开。首次使用需重新填写 API Key；不要将密钥发给维护者。
4. 系统可能请求钥匙串访问授权，尤其在更新本地签名包后。只对确认来自本项目的应用授权。拒绝时密钥可能无法读取或保存；不要通过关闭系统安全功能解决。

下载包将课表和聊天保存在 `~/Library/Application Support/QIAN YU/LocalDistribution/`，不依赖需要开发者团队身份的 App Group 数据库，也不启用 CloudKit。它不会自动读取 Xcode 签名版本的课表和聊天；原有数据保留在原位置，课表可以通过原始 `.ics` 文件重新导入。

该包采用 ad hoc 本地签名，没有 Apple Developer ID 签名或公证。“仍要打开”是用户确认来源后的系统操作，不能证明软件安全。小组件共享数据、通知和日历权限需要在实际安装环境验收。若下载包无法正常使用，可回到源码方式，选择 My Mac，用自己的账号在 Xcode 运行。

参考：[Apple：安全打开 Mac 应用](https://support.apple.com/en-au/102445)。

## 维护者打包与发布

先运行 `bash Scripts/check_project.sh`，再运行：

```sh
bash Scripts/package_macos.sh
```

默认输出到被 Git 忽略的 `build/distribution/`，包含 ZIP、SHA256SUMS.txt 和构建日志。可用第一个参数指定输出目录。脚本从当前源码构建，不包含个人 API Key、课表文件或聊天数据库。

iPhone 侧载包使用 `bash Scripts/package_ios.sh`，输出到 `build/ios-sideload/`。它构建设备 arm64 Release，启用 `QIANYU_SIDELOAD` 使用应用内的本地数据库，保留扩展，以本地签名附带可供 SideStore 读取的能力声明。安装仍必须通过 SideStore 的个人账号重新签名。输出 IPA、源索引、构建信息及 SHA-256 校验文件。

`.github/workflows/ios-sideload.yml` 在 main 的相关文件更新或手动运行时执行回归检查和打包，并更新独立的 `ios-sideload` 预发布频道，不改动版本发布标签。该频道的标签始终指向当前成功发布的源码，资产和源索引一起更新；构建发布只使用仓库发布令牌，不包含个人签名凭据。SideStore 安装能力和续签仍由设备与个人账号决定。

脚本仅为 Mac 分发构建启用 `QIANYU_LOCAL_DISTRIBUTION`，将密钥存储切换到独立的登录钥匙串项目。普通 Xcode 构建和 iPhone 构建继续使用原有存储方式。

公开上传前，在另一台 Mac 验收：解压安装与首次启动、API Key 保存和退出后读取、发送测试通知、课程与聊天持久化、日历同步、小组件更新，以及覆盖升级后的数据。校验签名成功和应用启动成功不能代替这些功能验收。完成素材授权核对后再将 ZIP、校验文件和说明上传 Release，并如实记录尚未通过的项目。
